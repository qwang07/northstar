# 条款承重性 A/B 对照法

**这一层回答的问题：这条教条**改变行为了吗**——还是模型本来就会？**

同目录 `platform-notes.md` 管的是另一件事（绑定层说明能不能被消费）。两份互不替代。

## 为什么单独一层

本仓跑过的验证共四层，**证明力不可互相替代**：

| 层 | 手段 | 证明 | 不证明 |
|---|---|---|---|
| 1 文本形态 | `tests/structure.py` + 变异检查 | 教条的结构不变量成立 | 与模型无关 |
| 2 文档可用性 | 天真子代理压测（文档作为输入喂进去） | 文档若被读，读者能照做 | 会不会被读 |
| 3 送达与可检索 | 点名问「某某相的某条款是什么」 | 文本已到消费端、可被检索 | **行为改变** |
| 4 承重性 | **本规程** | 这条教条真的改变了行为 | —— |

第 3 层最容易被误当成端到端——**点名问答是一次朗读，不是一次干活**。

**教条只在「模型默认行为与家规分岔」处承重。** 模型本来就会做对的事，写进教条是冗余：占篇幅、被摘要丢掉、还让人误以为它在起作用。分岔在哪，只有对照组能告诉你。

## 方法

1. **题面自然，不点名技能**——靠触发词自然触发（如"照这份 README 给这个模块写测试"含"写测试"）。点了名就退回第 3 层。
2. **夹具放中立目录**（`/tmp/...`），**不要放在本仓内**——否则项目上下文与仓内文档会污染两臂。
3. **处理臂**：本机常规会话跑同一题，结果落文件再取（长任务会超出单次调用上限）。
4. **对照臂必须换机器。**
5. **判据二值**：交付了产物 vs 拒绝交付并回踢；或任何一个"做 X 还是做 Y"的分岔点，事先写下两种预期。

### ⚠️ 同一台机器上没有干净的对照臂（实测）

模型有文件工具，教条就在磁盘上，**关不掉**：

- `--disable-slash-commands`（号称"禁用全部技能"）→ 无效。它直接去读了插件缓存，还报出"本机有 0.8.4–0.9.7 多个版本"。
- `--bare`（跳过插件）→ 不可用。它强制走 API key，OAuth 登录失效。

可行对照 = **另一台不装本插件、也够不着其缓存的机器 / 环境**。代价是两臂 harness 有别，须在结论里声明，别当成同一条件下的对照。

## 判读与处置

- **承重**（两臂分岔）→ 条款有效，此时才谈得上打磨措辞。
- **冗余**（两臂一致）→ **瘦身或删除，不要继续打磨措辞**。给一条不改变行为的条款润色，是在给自己制造"已加固"的假象——与恒真断言同型。
- **不确定**（分岔小 / 只在措辞不在行为）→ 换一个更靠近该条款的夹具重试；两次仍不确定，按冗余处置。

**分岔的实质常常不是"对照臂笨"**。它可能识别出同样的问题，只是仍然把产物交了出去。**软建议与硬门的差别就在这里**，这正是教条的价值所在——判读时看的是**动作**，不是**认知**。

## 留档纪律

每次记：日期、条款、夹具、两臂题面是否逐字相同、分岔点、判读结论。**判为冗余的条款要真的删或缩**——查了却不处置，这一层就退化成又一个立了没人用的机制。
