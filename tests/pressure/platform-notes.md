# 平台执行说明·天真子代理压测规程

**本规程只管一件事：绑定层说明能不能被消费。**「某条教条是否改变了行为」是另一层，见同目录 `clause-ab.md`。

**这是「兑现类契约两层量具」的第二层。** 第一层（`tests/structure.py` 的 T4a-e / T5）只测结构不变量——覆盖齐全、落点互异、落点确含被翻译一侧没有的记号。它判得死"关键词各写一遍"的空壳，**判不出"写了参数但消费方拨不出去"**。那一层归本规程。

结构层全绿 ≠ 兑现已验证。两层都过，才算这份说明兑现了它自己的声明。

## 谁跑、何时跑

- 改动任一 `platform-*.md` 之后；
- 发版前（与结构测试同为发版门的检查项）；
- 平台侧接口有变、或某次真实派发出过意外之后。

## 怎么跑

派**零上下文子代理**，一平台一个，判断类高档。硬约束写进派发提示词：

1. 输入**只有该平台执行说明的全文**，不给任何其它文件、不给对话背景；
2. 明令**不得读取文件、不得搜索代码库、不得动用训练记忆里关于任何具体平台或工具的知识**；
3. 明令**不得追问**，文档没说清就写「文档未说明」或「说了但不足以照做，缺 X」，**禁止用常识补**；
4. 逐题作答，每题给：结论 + 依据（文档哪一节）+ 是否有不足以照做之处。

第 2、3 条是这套量具的命门。允许它调用记忆，它会用平台知识替文档补洞，压测立刻退化成"这个模型知不知道这个平台"——测的就不是文档了。

## 题目集（固定六题）

| # | 题 | 考什么 |
|---|---|---|
| Q1 | 教条声明「工具面 = 只读，推理档位 = 判断类高档」，这一次派发要传哪些调用参数？逐个写出参数名与取值。 | 档位翻译 + 工具面兑现 + 参数清单是否足以拼出一次真实调用 |
| Q2 | 这次派发属于零上下文两把刀之一。除 Q1 的参数外，还要做什么才能让零上下文真正成立？具体到往提示词里放什么、不放什么。 | 能力表第 1 项的兑现 |
| Q3 | 派发前、派发后各要做哪些具体动作？**什么算"核验没过"——判定标准是什么？**没过时怎么处置这次派发的结论？给出会实际执行的命令。特别地：子代理只在仓库里留下一个临时日志文件，算不算没过？怎么办？ | 只读三步 + 判定口径 + 失败处置是否落到可执行命令 |
| Q4 | 并行派三个执行者同时改同一个仓库，怎么防冲突？给出具体做法。 | 执行三形态第三态 |
| Q5 | 派发之前有没有必须先完成的平台前置？有没有必须避免的设置？ | 前置与禁设项（静默失效类陷阱） |
| Q6 | 这份文档里有哪些地方你**照着做不了**——写了但不足以落到一次真实调用上？逐条列出，不要客气。 | 发现题，不计分，产出待裁清单 |

## 判据（手写，独立于被测说明）

**判据是人工从契约提炼一次、手写在此的，不得由被测说明自动生成**——否则期望值与被测物同源，就是镜像断言，恒绿。说明的契约变了，判据须由人重新推导，不做自动同步。

原则：**稳定条款钉死内容，易变条款只钉形状。**

### 双平台通用要点

- **Q1**：三档位的落点须两两不同，且答出的参数名确属该平台派发接口（易变部分——型号名——只钉"给出了具体取值"，不钉取值本身）；「工具面 = 只读」须答出该平台的兑现路径，且**若该路径需要调用参数，参数名必须在文档给出的参数清单里能找到**。**否定性陈述须可界定范围**——说明若称某能力"无对应参数"，答题者须能说出该否定限于哪个接口或通道；把接口级否定读成"本平台一律不可能"即记红。
- **Q2**：须答出「输入封闭」——只放 README + 测试/清单 + 本轮 diff，不放主会话背景；平台层若另有零上下文机制（如不继承对话轮次的参数），须一并答出。
- **Q3**：须答出三步（派发前记基线 / 提示词明令 / 返回后比对），**且基线取值与回滚都落到可执行命令**；失败处置须齐三件：判决作废、回滚越权改动、BLOCKED 升级给人。
- **Q4**：须答出以独立 git worktree 隔离，并说明该平台是内建原语还是手工建。
- **Q5**：须答出该平台的前置（有则说有、无则说无）与禁设项。

### 判定

- 每题**要点全中为绿**，缺一点即该题红。
- 以下一律记红：追问、用常识或训练记忆补文档没写的、对文档明明写了的内容答「文档未说明」。
- 对文档确实没写的答「文档未说明」**不记红**——那是判别力，不是失败；它落进 Q6 的待裁清单。
- Q6 逐条**人工裁**，三分：**真缺口**（属绑定层职责却没写清 → 修说明）／**越界**（属教条、过程或平台 API 自身的地盘 → 不修，理由留档）／**表述缺陷**（写对了但读者会误解 → 改写一句）。

### Q6 三分裁决（两轮合并）

**越界，不修**（属教条、过程或平台 API 自身的地盘）：SKILL.md 正文与零上下文红线（人格现场组装，教条是唯一来源，本就不该在绑定层复述）· BLOCKED 升级渠道与格式（过程态，教条地盘）· worktree 并行完成后的合并流程（implement 教条地盘）· 型号可用性与订阅降档（已指向安装指引，指针有落点）· 派发接口的调用签名与参数结构（平台自身 API 文档，非 northstar 契约）· 超时 / 重试 / 异常处理（未声明不派生）。

**表述缺陷，已改**：`isolation` 与「不接受工具面参数」的表面矛盾（Claude 侧已加范围界定）。

**真缺口，已裁并修（第三轮）**：

- **「越权改动」的判定粒度**（双平台共有，最硬）。原文无判据：`git status --porcelain` 同时列已跟踪修改与未跟踪新增，只读评审若产生临时文件算不算"动过手"，消费方只能自行拿捏。**裁定：严格口径**——两次取值逐字一致才算通过，未跟踪新增一并计入，**不设白名单**（白名单一开，它自己就是下一个后门）。配套一半必须同时落：第 2 步明令须交代"中间产物写到仓库之外"，否则严格口径只会制造误报。回滚按差异类型分派，HEAD 变了不自行回滚、直接升级。
- **参数取值域不全**（轻）：Codex `agent_type` 标注为不指定取默认、取值域未实测；Claude `isolation` 补默认语义，`run_in_background` 改为"显式传关闭，不倚赖默认"（默认值未实测，不假装知道）。

## 留档纪律

每轮压测记：日期、被测说明的版本或提交号、逐题红绿、Q6 三分裁决结果。**红转绿必须由说明的改动带来，不得靠调题目或松判据**——那是软化测试，与「防作弊门」同源。
