# discover —— 目标发现（发散相）

回路最前端。契约相的硬门只保证「契约经用户确认」，却假定**目标本身是对的**——目标错了，整条回路会忠实地收敛到一个错目标上，且没有任何一相会发现"这功能根本不该做"：write-test 忠实投影契约，audit 只审自洽，implement 只管红变绿。本相补的正是这一段。

## 与契约相的分界：两种相反的纪律

| | 本相（发散） | brainstorming（收敛） |
|---|---|---|
| 姿态 | 悬置判断，先把可能性摊开 | 逼问、排除、定案 |
| 产物 | 经确认的目标陈述 + 选型结论 | README 契约条款 |
| 典型失败 | 过早收敛——第一个想法就当答案 | 迟迟不定案 |

两种纪律共处一相会互相污染：还没探完可能性，"该定契约了"的紧迫感已经在筛选。故本相独立——多一次相位切换，换两种纪律各自纯粹。

## 触发与豁免

新需求到达时、进契约相之前。**豁免**：目标明确且低风险的小任务（改个字、修一个已归因的缺陷、用户已给出确定方案）直接进 brainstorming——本相不是每次都要走的仪式。

判豁免只问一句：**这个目标为什么值得做，答案是否已经清楚且无争议**？是 → 豁免；犹豫 → 不豁免。

## 四件事

1. **目标对齐**：陈述的目标往往只是**候选手段**。逐层问"它解决的是什么问题""不做会怎样""有没有更直接的路"，直到触达真实目的。手段可换，目的不可猜——把手段当目的，是最贵的一类返工。
2. **优先级取舍**：做不做、现在做还是以后做、几个之中先做哪个。给出取舍依据（成本 / 影响面 / 可逆性 / 依赖顺序），**不静默替用户排序**。
3. **可行性探针**：目标未显影时，**小步可逆**地试探——最小实验、读现有代码、跑一次真实数据。以事实换猜测，不靠想象决断。
4. **技术选型**：不可逆或高迁移成本的决策（存储、协议、框架、外部依赖）**先验证再定**——至少两个候选、各自取舍、给推荐；"为什么不选另一个"一并记下（过程态出境）。

## 纪律

- **发散优先于评价**：先摊开再筛选。只出一个方案就下结论 = 本相没做。
- **一次一问**：不一口气轰炸；拿得出选项时优先给选项。
- **探针可逆且不进主干**：任何试探都能撤销；探针代码是取证工具，用完即弃，真要保留则走正规回路。不可逆的试探本身就是需要人确认的动作。
- **不写 README**：契约唯一写入口是 brainstorming。本相产出交棒过去，不自行落契约。
- **YAGNI 前置**：本相最有价值的产出常常是**"不做"**——把不该做的挡在回路之外，比在回路里把它做得优雅便宜得多。

## 机制

主会话执行，**不派子代理**——本相的本质是人机对话，与 brainstorming 同理。需要摸清代码现状时用只读检索（横切能力，任何相可用）。

## 出口

- **目标确认** → 交 **brainstorming** 开题：附**目标陈述**（要达成什么、怎么算达成）+ 选型结论（若有）+ 已排除的备选及理由（过程态出境，不入契约）。
- **裁决不做 / 押后** → 结案，理由出境。**这是合法出口，不是失败**。
- **目标依赖未知事实** → 探针取证后重入本相；取不到证据则升级给人。

**收敛阀**（口径独立，不属「契约回踢类」枚举）：同一目标经三轮探针仍给不出**可判定的成功标准** → BLOCKED 升级给人，附各轮探针与所得。探不出成功标准，通常意味目标本身不成立，或提问的层次错了——那是人要裁的事，不是再探一轮能解决的。

## 不变量

1. **不下钻实现**：本相只定"做什么、为什么"，不定"怎么实现"——后者是契约相与实施相的领地。
2. **不产契约**：产物是交棒材料，不是 README 条款。
3. **过程态出境**：备选方案、探针记录、选型理由一律出境；契约只收结论。
