# audit —— 设计产物独立评审

评审层、独立。双检查点：
1. **契约审**（brainstorming 定稿 README 后）：跨模块目标（落了项目级 / 横切层条款或拓扑分解）必做——契约先审再派生测试，省返工；单模块目标可省，留到合卷一次审。审 README。
2. **合卷审**（write-test 完成后，implement 之前必过）：审 README + 测试；免测试分支审 README + 验证清单（清单即该分支的"测试"，审项同样适用）。

## 核心机制：零上下文（硬性）

audit **必须由零上下文子代理执行**——不是"优先"，是硬性。同 session 的当前 agent 记得整个设计对话，它会用记忆补全契约缺口，正是 audit 要消灭的；故当前 agent **不得自审、不得"假装失忆"代审**。write-test 的轻量自检同理不算数——作者自查稀释不了知识诅咒。
- **平台依赖**：本 skill 依赖平台的子代理能力。环境无法派子代理 → audit **不可执行 → BLOCKED 升级给人**，绝不降级为当前 agent 假装失忆审。
- **派发声明**：工具面 = 只读 · 推理档位 = 判断类高档。（只读如何兑现与核验见项目 README「跨平台拓扑·横切约束」；档位如何落成调用参数见平台执行说明，此处均不复述。）
- **dispatch 红线**：派发 audit 子代理时，prompt 里**只有 README + 测试（或验证清单）+ 本轮契约 diff**（diff 相对**回合起点**计算——起点由回合入口相记录、终点即当前，派发者给出，不靠审者猜，通则见项目 README「节奏·回合起点与固化」条；diff 是契约的变更内容，不是设计对话——它只说改了什么，不说为什么这么改，故不破坏零上下文）。controller **不得**附加任何解释、背景、项目导言或"这个项目是做什么的"。最隐蔽的失效不是假装失忆，而是 controller **好心补一句背景**、把记得的上下文偷渡给子代理——零上下文当场破功。严禁这种善意泄漏，亦严禁夹带"参考之前讨论""按说好的方式"等指向对话历史的指令。**也不得预判发现**——禁写"别标 X""顶多 Minor"：预判 = 替审者裁决，独立性同样当场失效；让它提、你在回合里裁。**给了 diff 的代价必须对冲：不得因 diff 未涉及而跳过审查**——五审项对全部在场材料适用，diff 只用于判归属，不用于缩小审查范围。用降低审查深度换收敛性，等于拿掉本相的价值。

## 五审项

1. **完整度**：零上下文读者能否仅凭 README + 测试 / 清单把这一层建出来？建不出 → 意图没声明全。
2. **契约↔测试一致**：测试 / 清单是否忠实投影 README——没有断言了 README 未声明的，也没有 README 声明了却无覆盖的。
3. **边界卫生**：各层 README 零重叠——每条契约仅在其权威层声明（拓扑 / 边界 / 接缝归项目级，横切约束归其横切层，内部行为归模块级），下层以指针承接不复述——**项目级契约显式声明的复述例外不计缺口，但例外须自带枚举集合与守护方式，否则仍计**；无时态（过程态没渗进契约）；接缝接口契约 I 在每条边上都在（拓扑边只在项目级 README 在场时查，单模块材料无边则此子项不适用）。
4. **内部一致**：有无相互矛盾的条款；有无能被两种读法解释的歧义。
5. **断言强度**：测了但断言恒真 / 过弱 = 零判别力——审项 2 只查覆盖，本项查判别力。逐条问：把实现改错一位，它会红吗？恒真断言、只断状态码不查 body、松匹配枚举、精度不锁，一律计缺口。清单分支对应查：每条是否机械可判定（有判定命令 / 可观察证据，答案非"是"即"否"）。

契约审检查点只有 README 在场，审项 1、3、4 适用；2、5 留待合卷审。

## 判决（两级）

门控与出境必须分开，否则门永不收敛——存量债恒在，全量判决就恒不通过。

**一、本轮判决（放行依据）**：本轮改动是否引入了新的不自洽。无新缺口 → 放行下一相。

**二、存量报告（出境依据）**：与本轮改动无关的既有债。**不参与本轮门控**——逐条列出交 controller 出境（过程态；去向不由教条声明），不阻塞交棒。

**报告须自带排序**（硬）：无序清单在收口清账时等于没排——条目一多就按出现顺序处理，**成本最低、收益最大的那些反而压在最后**。每条给三个 1-5 分，按公式排序：

```
优先级 = (影响 + 风险) × (6 - 成本)
```

- **影响**：不修的后果有多大（波及面 × 严重度）；
- **风险**：它继续存在会诱发什么新缺陷；
- **成本**：修它要多少工。

成本项**取反相乘**而非相减——低成本项由此被乘法放大，这正是意图：先摘够得着的果子。分值与打分理由随报告出境，不入契约。

**打分口径**：三项均为**同轮内的相对打分**，不追求跨轮可比——跨轮比分数没有意义，也不必为此维护校准表。同轮内打完通读一遍，若排序明显反直觉，改的是分不是公式。

每条并标**债务类型**：**代码**（可读性 / 重复 / 复杂度）· **架构**（边界错位、层级穿透）· **测试**（覆盖漏、断言弱、跑得慢）· **依赖**（过期、弃维、许可）· **契约**（README 条款过时或含糊）· **基础设施**（构建、发版链路、环境）。
**同分时按类型再裁，判据是「拖着会不会变贵」**：架构债与契约债越拖越贵（后续每一轮都在它的错误前提上加码，成本随时间单调上升），优先；依赖债随上游脱节加速变贵，次之；代码 / 测试 / 基础设施债成本大体恒定，可后置。**这条判据本身可推翻**——某条债若有明确的到期日（许可到期、上游停止安全更新），按到期日排，不按类型。
**契约债特判**：它一旦被认定，正确去向是**当轮回踢 brainstorming，不等收口清账**——契约错着，后面每一轮都在错的前提上派生测试与实现。它进存量报告只是为了留痕可追溯，不是排队等着。存量报告里的契约债若跨轮不动，本身就是一条更该报的债。

**归属判据**：一条缺口属"本轮引入"，当且仅当它由 diff 中的改动直接造成，**或由该改动使既有条款失效**。后者是关键且易漏的一类——改动可能让一条未改动的条款不再成立，那仍算本轮引入，按行归属抓不到它。归属存疑时**按本轮引入计**（宁严不宽）。

本轮判决有缺口时 → **回踢上游分流**：契约缺口（意图缺失 / 含糊 / 矛盾 / 边界不清）回 **brainstorming**；测试缺口（覆盖漏 / 断言弱 / 越界断言 / 清单不可判定）回 **write-test**。越界断言（测试断言了 README 未声明的）默认按测试缺口回 write-test 删改——README 是权威；若它暴露的其实是漏声明的真实意图，则同时报契约缺口回 brainstorming，两格分不清时并报、在人 Gate 裁。**audit 只指出缺口，绝不自行补写**——自补等于评审者僭越成作者，独立性当场失效。

**收敛阀**：**本轮判决**的同一缺口被反复回踢达阈值（默认 3 次）仍不过 → BLOCKED 升级给人，附该缺口回踢历史（过程态出境），不再自动放行 / 回踢。**存量报告项不计入本阀**——它们出境记录，不参与门控计数。

## 退出

**本轮判决**无新缺口 → 交棒：契约审过 → write-test；合卷审过 → 人 Gate → implement。存量报告不阻塞交棒，但须已出境（有去向、可追溯），不得就地丢弃。出境不是终点——历轮存量报告在项目收口时逐条清账（回收路径见 brainstorming「收口」节，此处不复述）。
