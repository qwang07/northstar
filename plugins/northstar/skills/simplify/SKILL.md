# simplify —— 收尾链第一道工序（只改写法，不改行为）

implement **退出门全部通过**之后（条件见 implement 的「退出」节，此处不复述），code-review 之前。只做一件事：**不改变行为地降低本轮改动的维护成本**。

## 边界：与 implement 内循环重构的分界（双判据）

implement 内循环第 4 步「重构」清理的是**刚写的那点**，本相清理的是**整轮改动**。两者不重复，判据有二，缺一不可：

| | implement 内循环重构 | 本相 |
|---|---|---|
| **粒度** | 单条测试转绿后就地清理，范围是刚写的那几行 | 全轮全绿后横向看整轮改动，能看到跨条目的重复与抽象层次问题 |
| **独立性** | 执行者是写码者本人，带写码记忆 | 执行者**无写码记忆**——不知道「为什么这么写」，所以能看出它绕 |

**独立性是本相存在的理由**：写码者知道自己每一步的意图，那份记忆恰好掩盖了绕路——「我记得这里必须这样」和「这里本来就该这样」在自己眼里长得一模一样。

本相的独立性是**零写码记忆**：执行者不知实施过程，且**动手改**。这与 audit / code-review 的只读评审是不同的机制——派发时别把本相当那两把刀套用，输入给错节奏就跑不起来（本相要测试与工作区，只给 diff 跑不动）。

## 机制：独立执行者（硬性）

本相**必须派独立执行者**——不是「优先」，是硬性。主会话记得整个实施过程，自己精简 = 假装失忆，独立性当场破功。

- **平台依赖**：环境无法派独立执行者 → 本相**不可执行 → BLOCKED 升级给人**，绝不降级为主会话自精简。
- **dispatch 输入**：本轮改动的 diff（范围由派发者界定并给出，不靠执行者猜）+ 测试 + 模块 README。**封闭的是上下文，不是资源**——不给 session 历史、不叙述实施过程（「我们当时是这样做的」一旦漏进去，独立性即失效，同 audit / code-review 的 dispatch 红线）；但本相要动手改代码并跑全套，工作区与可运行环境必须给到，不适用只读评审那种「仅看 diff」的封闭。README 在此不作合规裁决用，只供识别「这处绕是契约要求的」而不误剪。

## 节奏：一处一改，绿为准绳

1. 逐处审视本轮改动：消除冗余与不必要的嵌套、抽象，收拢同类逻辑；命名直白；删除复述代码的注释。
2. **明晰优先于紧凑**——显式代码胜过聪明的一行流。
3. **不过度精简**：不合并不相关的关注点，不拆掉改善组织的抽象。
4. 一处一改，改完跑全套；保持全绿才留下。
5. 变红即撤销该处，**并报告**——见下节。

## 出口

**精简致红 → 先自证，再分流。** 测试变红有两个原因，**默认假定后者**：① 那条测试在断言实现细节（违反「测意图不测实现」铁律）；② **精简者自以为只改写法，实则改了行为**。

撤销该处后，须对该改动**自证行为等价**——逐条说明改动前后在什么输入下行为相同；给得出理由才算自证，"我觉得等价"不算。

- **自证不出 → 判为 ②**：该改动错，撤销结案，不报回踢项。**默认走这条**，不给"可能是测试的问题"留活口。
- **自证通过 → 判为 ①**：升格为回踢项报 write-test，附哪条测试、被什么改动触红、行为等价的自证理由。

本相是全回路唯一能自然撞见 ① 的位置，但撞见 ① 的前提是先排除 ②——否则本相就成了绕过「防作弊门·不得软化测试」的后门。

**疑似 bug / 契约缺口 → 只报告，不动手。** 本相不修 bug、不补契约。报告交回派发者，按 code-review 的「复核 → 三岔 → 实施」处置（属实且是实现问题 → 满足它；根在契约 → 回踢 brainstorming；不属实 → 有据驳回）。

## 不变量

1. **行为不变**：全套测试是行为不变的唯一守护。某段代码无测试可跑 = 该段不在本相 scope 内（判据见「适用范围」节）。
2. **测试与 README 只读**：不改测试迁就精简，不改契约迁就代码。
3. **范围仅本轮改动**：未触及的相邻代码不碰——顺手重构是范围外副作用，属另一轮的事。

## 适用范围：按代码判，不按分支判

判据是**该段代码有无持续测试守护**，不是本轮属哪个分支——write-test 明确「同一轮两类可并存」「同一条声明也可拆两半」，故混合轮是常态。

- **有持续测试守护的代码** → 在本相 scope 内。
- **无持续测试守护的代码**（纯一次性操作：迁移 / 灌数 / 一次性脚本）→ **不在 scope 内**：「一处一改跑全套保持绿」对它无从执行，不精简。
- 本轮全部代码皆无守护 → 本相整体跳过，验证清单逐项过后直接进 code-review。

## 退出

本轮改动精简完毕（或判定无可精简）、全套仍绿 → 交 code-review 出收尾质量刀。

**交付物**：精简后代码 + **精简点清单**（每点一句话，说明改了什么；无可精简则明说）+ 两类报告项（见「出口」）。

**未决回踢项不阻塞收尾链**：自证通过的回踢项报出后不拦 code-review，交派发者带出本轮处置。被撤销的那处精简不在本轮补做。

**不重跑 implement 的实证验证门——仅限本相改动**：本相行为不变，全套全绿即为担保，implement 退出时已过的实证验证不因**本相的精简**失效。致红且自证失败者已撤销、回到全绿态，同样不影响。
**本条只覆盖本相**：收尾链内其他环节若产生改行为的代码（如 code-review 发现处置的「满足它」一岔），其是否需重过 implement 各门，本契约不表态——**不得援引本条作为豁免依据**。
